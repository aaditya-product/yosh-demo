# 06 · Demo engine

Scripted behaviour lives entirely in `src/demo/`, separate from UI. No component
contains demo logic. No AI calls. No network.

## Why it's separate

Screens must work as ordinary UI. The engine sits above them dispatching store
actions on a timer. This keeps screens reusable and makes the script editable
without touching components.

## Shape

```ts
type Trigger =
  | { kind: 'voice',  screen: string, match: string }
  | { kind: 'type',   screen: string, match: string }
  | { kind: 'click',  dataId: string }

type Effect = { after: number, action: StoreAction }   // ms from beat start

type Beat = {
  id: string
  trigger: Trigger
  transcript?: string[]      // words, staggered 120ms, for voice beats
  effects: Effect[]
}
```

`match` is a loose contains-check, lowercased. The presenter must not have to
type an exact string. `"towel"` should match `"can we get some towels"`.

**Fallback rule:** if input on a voice-enabled screen matches no beat, run the
nearest beat for that screen anyway. A demo must never show a dead end. Log the
miss to console.

## Beats

### `b1-multi-intent` — Beat 1

```
trigger    voice on G-03, match: "table" OR "eight" OR "ac" OR "rattl"
transcript ["We","need","the","table","set","for","eight","tonight,","and",
            "the","AC","in","the","study","is","rattling."]
effects
  0      setVoiceState('listening')
  2200   setVoiceState('parsing')
  3000   showConfirmCards([
           { type:'gathering',   title:'Gathering setup',
             fields:[ {covers:'8 covers'}, {when:'Tonight, 19:30'},
                      {where:'Main House dining'} ],
             source:'table set for eight tonight' },
           { type:'maintenance', title:'Maintenance',
             fields:[ {issue:'AC — rattling'}, {location:'Study'},
                      {priority:'Normal', confidence:'low'} ],
             source:'the AC in the study is rattling' }
         ])
```

On confirm of each card: `createRequest(...)` with `origin: 'voice'`,
`requester: 'aisha'`, `property: 'villa-12'`, `status: 'new'`.

Confirming both → navigate `G-05`.

### `b2-assign` — Beat 2

```
trigger    voice OR type on L-03, match: "assign" OR "rahul"
effects
  0      setVoiceState('listening')
  1800   setVoiceState('parsing')
  2400   showActionCard({
           title:'Assign request',
           fields:[ {request:'#0BE · AC rattling'},
                    {staff:'Rahul Menon'},
                    {eta:'ETA 40 min → {now+40m}'} ]
         })
```

On confirm:
```
  0      assignRequest(reqId,'rahul'); setEta(reqId, now+40m);
         setStatus(reqId,'assigned')
  300    showToast('Assigned to Rahul Menon', { undo: true, ms: 6000 })
```

Genie re-renders from the store automatically. **Do not add a Genie-specific
effect** — if the shared store isn't driving that update, the architecture is
wrong and the beat is a lie.

### `b4-finding` — Beat 4

```
trigger    click on L-05/fail  (item 3)
effects
  0      expandFindingForm()
```
```
trigger    voice on L-05, match: "lock" OR "chemical" OR "broken"
transcript ["Chemical","store","door","lock","is","broken,","needs","replacing."]
effects
  0      setVoiceState('listening')
  2000   setVoiceState('parsing')
  2600   fillFinding({ severity:'High',
                       note:'Chemical store door lock is broken, needs replacing',
                       photo:'plant-room.jpg' })
```

On finding save:
```
  0      recordFinding(inspId, itemId)
  400    createRequest({ type:'maintenance', origin:'inspection',
                         title:'Replace chemical store door lock',
                         priority:'high', property:'villa-12' })
  400    createActionPlan({ finding, ownerId:'priya', dueAt:now+72h })
  900    showCreatedLink(newRequestRef)
```

The 400ms delay matters — the corrective task must appear to be *generated by*
the finding, not to have existed already.

### `b5-warehouse` — Beat 5

```
trigger    click on L-08/action-warehouse
effects
  0      showConfirmCard({ title:'Warehouse request',
                           fields:[ {item:'Table linen'}, {qty:'12'},
                                    {destination:'Villa 12 · Linen store'} ] })
```

On confirm:
```
  0      createRequest({ type:'asset', origin:'command', status:'open' })
  1400   setExternal(reqId, { system:'D365', ref:'PR-4471' })
  1600   showToast('Sent to Dynamics 365 · PR-4471')
```

The 1400ms gap is the visible "handoff". Without it the badge just appears and
reads as fake.

## Presenter controls

Hidden panel, toggled with `Cmd+K`:

- Jump to any beat
- Reset store to seed
- Toggle voice input between microphone and typed (the room may be noisy — the
  presenter types, everything else behaves identically)
- Speed multiplier for rehearsal

This panel must never be visible during the demo unless summoned.

## Rule

Every scripted outcome dispatches a real store action. Nothing is faked at the
component level. If a beat can't be expressed as store actions, the data model
is wrong — fix the model, not the beat.
